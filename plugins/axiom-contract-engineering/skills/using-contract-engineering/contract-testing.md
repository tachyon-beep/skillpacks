# Contract Testing

**A contract suite is tested against the failure modes of contracts — drift, silent defaults, covert channels, forbidden arrivals — not against its own constructors. A test that round-trips a record built by the schema's own constructor proves only that the code agrees with itself.**

## When this earns its cost

Read this sheet when:

- A boundary has tests, they pass, and producers and consumers still disagree in production about what a field means.
- You are reviewing a test suite for a versioned record and want to know whether it can *fail* for the reasons contracts actually fail.
- A schema declares absence, rejection, forbidden fields, or version gates, and you want evidence those declarations are enforced rather than documented.
- A unit change, a normalisation change, or a version bump is about to ship and the only safety net is the existing suite.
- A resolver's output is supposed to be reproducible and nothing in CI has ever replayed it.

## The defect class: suites that cannot fail

Two shapes recur, and both look like diligence.

**The vacuous round-trip.** The test builds a record with the schema's own constructor, serialises it by taking its own field dict, and parses that back:

```python
# WRONG — this test cannot fail for any reason a contract fails.
def test_round_trip():
    record = MetricsRecord(host_id="h1", cpu_util=Measured(0.4, 1000.0), schema_version=3)
    payload = record.__dict__.copy()
    assert parse(payload) == record
```

Every key is present because the constructor put it there. Every type is right because the constructor typed it. No absence path is reached, no version branch other than the current one, no legacy payload, no payload a real producer ever emitted. It proves the parser is the inverse of the constructor on the one input where that is trivially true. Meanwhile the actual failure — a v2 collector emitting `latency_ms` where the reader expects `latency_s` — is untestable by construction, because a constructor cannot express a wire dialect.

**The future-version test.** The second is worse, because it *pins the wrong behavior*:

```python
# WRONG — this asserts fail-OPEN and locks it in.
def test_future_wire_version_still_parses():
    payload = {**GOLDEN_V3, "schema_version": 99}
    assert parse(payload) is not None        # "forward compatible"

# RIGHT — the inversion. Unknown means unknown.
def test_future_wire_version_rejected():
    with pytest.raises(ContractViolation, match="99"):
        parse({**GOLDEN_V3, "schema_version": 99})
```

A version field exists so the producer declares a meaning and the reader refuses meanings it does not know (`schema-versioning-and-evolution.md`). A test asserting that an unknown future version parses converts that refusal into a promise, made on behalf of producers that do not exist yet, that their semantics will match today's. When v99 ships with a changed unit, the suite stays green while every reader silently reinterprets. Any such test in a suite is inverted, not deleted — the assertion is *rejection*.

The general rule both cases violate: **a fixture must originate outside the code under test.** If the serializer under test produced it, the test compares the implementation to itself.

## The taxonomy

### 1. Golden wire fixtures, per version

Hand-written dicts or JSON files representing shapes real producers emit, checked in per version:

```text
tests/contracts/fixtures/
  v2/old_producer.json        # full v2 payload, ms units
  v2/partial.json             # v2 producer that lost a field to a serialization bug
  v3/new_producer.json        # full v3 payload, s units, gpu_util absent-able
  v3/absence_heavy.json       # every absent-able field explicitly absent
```

They are authored by hand from captured traffic or the spec — **never generated by the serializer under test**. Each is parsed and asserted against a fully spelled-out expected record, not a spot-check of two fields:

```python
@pytest.mark.parametrize("path", sorted(FIXTURES.rglob("*.json")))
def test_golden_fixture_parses_to_expected(path):
    payload = json.loads(path.read_text())
    expected = EXPECTED[path.relative_to(FIXTURES).as_posix()]   # spelled out in the test module
    assert parse(payload) == expected
```

**The meaning-pin.** Fixtures catch shape drift; they do not catch a version whose *meaning* changed underneath it. Pin the canonical serialization of one golden record per version by hash:

```python
MEANING_PINS = {2: "9f0c…", 3: "4ad1…"}   # sha256 of canonical_bytes(parse(golden))

@pytest.mark.parametrize("version, digest", sorted(MEANING_PINS.items()))
def test_serialized_meaning_is_pinned(version, digest):
    record = parse(json.loads((FIXTURES / f"v{version}/canonical.json").read_text()))
    assert sha256(canonical_bytes(record)).hexdigest() == digest, (
        f"v{version} serialized meaning changed without a version bump"
    )
```

Changing a unit, a normalisation, or a field's basis without bumping the version now fails a test. This is the mechanical guard against version-in-name-only (`schema-versioning-and-evolution.md`), and updating a pin is the diff a reviewer must see.

### 2. Round-trips done right

Round-trips are worth having — over inputs the code did not author. Two sources qualify: golden fixtures, and generated records.

```python
@pytest.mark.parametrize("path", sorted(FIXTURES.rglob("*.json")))
def test_serialize_parse_serialize_is_stable(path):
    record = parse(json.loads(path.read_text()))
    assert parse(json.loads(canonical_bytes(record).decode())) == record

@given(records(version=3))                 # hypothesis strategy over the v3 schema,
def test_generated_records_round_trip(record):   # including Absent(...) in every absent-able slot
    assert parse(json.loads(canonical_bytes(record).decode())) == record
```

The generator must produce absence, boundary values, and zero — a strategy that only emits comfortable floats reproduces the vacuous test with more machinery.

### 3. Absence-path tests

Every absent-able field, crossed with every way absence can arrive on the wire — explicitly tagged absent, and omitted entirely:

```python
ABSENT_ABLE = ["cpu_util", "gpu_util", "queue_depth"]

@pytest.mark.parametrize("field", ABSENT_ABLE)
@pytest.mark.parametrize("form", ["tagged", "omitted"])
def test_absence_parses_to_typed_absence(field, form):
    payload = json.loads((FIXTURES / "v3/new_producer.json").read_text())
    if form == "tagged":
        payload[field] = {"absent": "not_sampled"}
    else:
        del payload[field]   # actually omit — `payload[field] = payload.pop(field)` would re-insert it
    value = getattr(parse(payload), field)
    assert isinstance(value, Absent) and value.reason is AbsenceReason.NOT_SAMPLED

def test_zero_is_a_real_measurement():
    payload = {**GOLDEN_V3, "cpu_util": {"value": 0.0, "measured_at": 1000.0}}
    assert parse(payload).cpu_util == Measured(0.0, 1000.0)   # not Absent, not falsy-collapsed

def test_consumer_abstains_on_missing_required_input():
    metrics = replace(GOLDEN_RECORD_V3, queue_depth=Absent(AbsenceReason.PROBE_FAILED))
    assert decide(metrics, POLICY).outcome is Outcome.INSUFFICIENT_DATA
```

The zero test is not decoration: it is the assertion that the absence encoding did not swallow a real measurement, which is the symmetric half of `silent-default-elimination.md`. The abstain test is the assertion that absence *changed the decision* rather than being encoded correctly and then ignored.

### 4. Version-gate tests, fail-closed

```python
def test_unknown_version_rejected():
    with pytest.raises(ContractViolation):
        parse({**GOLDEN_V3, "schema_version": 4})

def test_missing_version_rejected():
    payload = {k: v for k, v in GOLDEN_V3.items() if k != "schema_version"}
    with pytest.raises(ContractViolation, match="schema_version"):
        parse(payload)

@pytest.mark.parametrize("version", sorted(SUPPORTED))
def test_supported_version_parses_under_its_own_semantics(version):
    record = parse(json.loads((FIXTURES / f"v{version}/canonical.json").read_text()))
    assert record.latency_s == pytest.approx(0.25)   # v2 wire says 250 (ms), v3 says 0.25 (s)
```

The unit assertion must use a value that *distinguishes* the units. A fixture with `latency = 1` passes under both interpretations and asserts nothing; `250 ms` vs `0.25 s` fails loudly if a branch converts twice, not at all, or in the wrong direction. And the suite contains no test claiming an unsupported version parses — see the defect class above.

### 5. Canonicalisation property tests: invariance *and* separation

Equivalence tests come in pairs. Invariance alone is half a proof — a canonicaliser that returns a constant passes every invariance test ever written.

```python
@given(record=records(version=3), noise=equivalence_noise())
def test_equivalent_inputs_canonicalise_identically(record, noise):
    """noise permutes field order, swaps aliases for canonical names, varies
    whitespace and float formatting, and repositions the record in a batch."""
    a, b = serialize(record), noise.apply(serialize(record))
    assert canonical_hash(parse(a)) == canonical_hash(parse(b))
    assert resolve(parse(a), STATE, POLICY) == resolve(parse(b), STATE, POLICY)

@given(record=records(version=3), data=st.data())
def test_semantic_change_separates(record, data):
    mutated = data.draw(mutate_one_semantic_field(record))
    assume(mutated != record)
    assert canonical_hash(mutated) != canonical_hash(record)
```

Every row of the covert-channel table in `deterministic-resolution.md` is an axis of `equivalence_noise`; every semantic field is a candidate for `mutate_one_semantic_field`. The invariance direction proves irrelevant variation cannot steer the output; the separation direction proves the canonical form did not collapse meaning it was supposed to keep. Ship both or neither (`canonical-identity.md`).

### 6. Schema-invalid rejection tests

For each forbidden shape, the assertion is a typed `ContractViolation` — never a defaulted or partially-populated record:

```python
INVALID = {
    "wrong_type":        {**GOLDEN_V3, "host_id": 17},
    "out_of_range":      {**GOLDEN_V3, "cpu_util": {"value": 4.2, "measured_at": 1000.0}},
    "contradictory":     {**GOLDEN_V3, "cpu_util": {"value": 0.4, "absent": "not_sampled"}},
    "malformed_union":   {**GOLDEN_V3, "cpu_util": {"measured_at": 1000.0}},   # neither arm
}

@pytest.mark.parametrize("name", sorted(INVALID))
def test_invalid_payload_rejected(name):
    with pytest.raises(ContractViolation):
        parse(INVALID[name])
```

`pytest.raises` is the whole point: a test asserting `parse(bad) == SOME_DEFAULT` documents the defect rather than catching it.

### 7. Authority tests: prove the forbidden field cannot arrive

Some fields must not reach a consumer at all — a reviewer's identity in a blinded view, an author's preference in a resolver input, a caller-supplied budget override. The test is not that the parser ignores them. It is that the parser **rejects** them:

```python
FORBIDDEN = {"ReviewerView": ["author_id", "team", "notes"],
             "ResolverInput": ["preferred_outcome", "requested_priority"]}

@pytest.mark.parametrize("cls, field", [(c, f) for c, fs in FORBIDDEN.items() for f in fs])
def test_forbidden_field_is_rejected_not_dropped(cls, field):
    with pytest.raises(ContractViolation, match=field):
        PARSERS[cls]({**GOLDEN[cls], field: "x"})
```

Silent dropping is the failure mode this test exists to prevent: a producer that keeps attaching `preferred_outcome` and never sees an error keeps believing it has influence, and the day someone "helpfully" wires the field through, the influence lands with no diff that looks like a policy change.

**Canaries need positive controls.** A blinded-view test plants a sentinel upstream and asserts it never appears downstream — but that assertion also passes if the sentinel was never planted:

```python
SENTINEL = "CANARY-7f3a"

def test_blinded_view_excludes_sensitive_field():
    upstream = build_upstream_record(author_id=SENTINEL)
    assert SENTINEL in canonical_bytes(upstream).decode()      # positive control: it IS present upstream
    assert SENTINEL not in canonical_bytes(blinded_view(upstream)).decode()
```

Without the first assertion the test is a tautology that survives every refactor that quietly renames the field.

**The closure walk.** Per-field tests miss the field added next quarter. Re-assert in CI the walk that `blinding-by-construction.md` defines: `FIELD_POLICY` is keyed by `(qualified class name, field name)`, and `assert_field_policy_closure` recurses through every record *reachable from the source root* — a top-level check on the view's own fields would miss the fingerprint added three levels down:

```python
def test_every_reachable_field_has_a_declared_policy():
    assert_field_policy_closure(CandidateRecord)   # raises UndeclaredFieldPolicy on any gap

def test_closure_walk_actually_fails_on_undeclared_fields():
    @dataclass(frozen=True)
    class Unregistered:                            # positive control for the control
        surprise: str
    with pytest.raises(UndeclaredFieldPolicy, match="Unregistered.surprise"):
        assert_field_policy_closure(Unregistered)
```

### 8. Resolver replay tests

```python
@pytest.mark.parametrize("case", sorted(REPLAY_CASES))          # (inputs, state, policy, expected_bytes)
def test_replay_is_byte_identical(case):
    metrics, state, policy, expected = load_replay_case(case)
    decision, _next_state = resolve(metrics, state, policy)
    assert canonical_bytes(decision) == expected

@given(record=records(version=3), tightening=restrictions())
def test_authority_is_monotonically_narrowing(record, tightening):
    base = resolve(record, STATE, POLICY)
    tighter = resolve(tightening.apply(record), STATE, POLICY)
    assert tighter.budget <= base.budget
    assert tighter.permissions <= base.permissions       # subset, on every authority axis
```

A more-restrictive input may never yield a less-restrictive output. That is the executable form of narrow-only authority (`deterministic-resolution.md`), and it catches widening through defaults that no example-based test enumerates.

### 9. CI-level complements

Two things the unit suite structurally cannot do:

- **Parse-version counters in production telemetry.** The suite proves each version branch works; only a production counter proves a branch is *unused*. Deleting a v2 branch on the belief that the fleet upgraded is an assumption; deleting it because the v2 counter has read zero for a declared window is evidence. Wire the counter, alert on unexpected versions, and gate branch deletion on it (`schema-versioning-and-evolution.md`).
- **Golden-file replay of captured real traffic, on every build.** Sample real payloads, redact, check them in, and parse the whole corpus in CI. This catches the class synthetic fixtures never will: *someone tightened the parser and the legacy fleet started getting rejected*. Hand-written fixtures encode what you believe producers emit; captured traffic encodes what they actually emit, including the field a collector has been misspelling for a year.

Both are contract tests that happen not to fit in a test function. Neither is optional at fleet scale.

### 10. The coverage rule

Coverage of a contract is not line coverage. It is a cross-product, and it is enumerable:

| Axis | Rule | Minimum |
|---|---|---|
| Version | Every supported version × at least one golden fixture, parsed and fully asserted | 1 fixture + 1 meaning-pin per version |
| Absence | Every absent-able field × {explicitly-absent, omitted} | 2 tests per absent-able field, plus one zero-is-real test per numeric field |
| Version gate | Unknown, missing, and each supported version | 3+, and zero tests asserting a future version parses |
| Forbidden | Every forbidden field × every record class it must not reach | 1 rejection test each, plus the closure walk |
| Equivalence | Every covert-channel axis (order, alias, whitespace/float format, batch position) | 1 invariance property + 1 separation property |
| Invalid | Every forbidden shape class (type, range, contradiction, malformed union) | 1 rejection test each |
| Replay | Every resolver × golden (inputs, state, policy) | 1 byte-identical case + 1 monotonicity property |
| Unknown fields | Per record class, matching its declared stance | Additive-safe: preserve-and-ignore asserted. Authority: rejection asserted. |

That last row is the one teams get inconsistent: **unknown-field handling is per record class, not per codebase.** A metrics record whose contract declares additive fields non-breaking must have a test proving an unknown key is preserved-and-ignored. An authority record must have a test proving the same key is rejected. If both classes behave the same way, one of them is wrong and the suite is not saying which.

## Rationalizations

| Rationalization | Reality |
|---|---|
| "We have round-trip tests, the parser is covered" | If the fixture came from the constructor or the serializer under test, the test asserts the code agrees with itself. Coverage of the parser's *lines* is not coverage of the contract's *failure modes*. |
| "Generating fixtures from the serializer keeps them in sync" | It keeps them in sync with the bug, too. A fixture's job is to be an independent witness to what a producer emits; generated fixtures change whenever the code changes, which is exactly when you need them not to. |
| "Testing old versions is dead weight, everyone's on v3" | Then a parse-version counter says so and the branch gets deleted — that is the retirement path. Untested-but-live is the state that fails; untested-and-dead should not be in the code. |
| "`test_future_version_parses` proves we're forward compatible" | It proves you fail open. Forward compatibility is a claim about producers you have not met; the test pins it in and the suite stays green while readers silently reinterpret. Invert the assertion. |
| "The blinded view has a canary test" | Does it have a positive control? Without asserting the sentinel is present upstream, the test passes when the sentinel was never planted, when the field was renamed, and when the builder silently dropped it. |
| "The parser ignores forbidden fields, that's safe" | Silently. So producers keep sending them, believing they matter, and the influence is one well-intentioned commit away from landing with no diff that reads like a policy change. Reject. |
| "Property tests are slow and flaky" | Flaky property tests are usually finding real nondeterminism. Slow ones get a smaller example budget in PR CI and the full budget nightly — the answer is scheduling, not deletion. |
| "Our fixtures are realistic, we don't need captured traffic" | Fixtures encode what you believe producers send. The defect class that matters is the gap between that belief and reality, and only real payloads can occupy it. |

## Red flags

- Any fixture built by the schema's constructor, the serializer under test, or a factory that shares code with the parser.
- A test named `test_*future*version*` that asserts success; any `assert parse(x) is not None` as the whole assertion.
- A schema with absent-able fields whose test module contains no `Absent` and no `isinstance` branch.
- Rejection tests that assert on a returned value instead of `pytest.raises`.
- A canary test with no positive control; a property test with an invariance direction and no separation direction.
- A version bump, unit change, or normalisation change in a diff that touches no fixture and no meaning-pin hash.
- An authority record class with no test that constructs a forbidden field and asserts rejection.
- A resolver with no replay case, or replay cases compared by `==` on parsed objects rather than on canonical bytes.
- Only the current version has fixtures; only the happy path has assertions.

## Quick reference

| Failure mode | Test that catches it |
|---|---|
| Producer/consumer drift in field shape | Golden per-version wire fixtures, hand-authored, fully asserted |
| Version-in-name-only (meaning changed, version didn't) | Canonical-serialization hash pin per version |
| Silent default on a missing field | Absence-path tests: every absent-able field × {tagged, omitted} |
| Absence encoded then ignored downstream | Consumer abstain test (`INSUFFICIENT_DATA` asserted) |
| Zero collapsed into "missing" | Explicit zero-is-a-real-measurement test |
| Fail-open version gate | Unknown → reject, missing → reject; no future-version-parses test exists |
| Double or missing unit conversion | Per-version assertion on a value that distinguishes the units |
| Covert channel steering the output | Equivalence-invariance property over every noise axis |
| Canonicaliser collapsing real meaning | Separation property: mutate any semantic field → different hash |
| Defaulted record from a malformed payload | Typed `ContractViolation` rejection test per forbidden shape |
| Forbidden field arriving (or being silently dropped) | Rejection test per (record class, forbidden field) + field-policy closure walk |
| Blinding leak | Sentinel canary **with** an upstream positive control |
| Unreproducible resolution | Golden replay, compared on canonical bytes |
| Authority widening | Monotonic narrow-only property test |
| Legacy fleet rejected by a tightened parser | Captured-traffic corpus replayed on every build |
| A version branch kept forever "just in case" | Parse-version counters gating deletion |
