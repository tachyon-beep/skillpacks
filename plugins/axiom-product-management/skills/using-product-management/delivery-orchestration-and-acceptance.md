# Delivery and Acceptance

Optional reference: use the parts relevant to the current question and selected policy. Existing records can satisfy the evidence; no fixed artifact count, review duration or reviewer count applies.

Connect each delivery unit to a product criterion, owner and tracker ID. Coordinate sequencing/engineering directly for small work or use relevant specialists for real uncertainty; no mandatory owner-pack hierarchy applies.

Track arrival separately from acceptance: engineering done, integrated, deployed, verified, accepted and value observed are distinct states. Read actual evidence rather than inferring from a closed ticket.

For acceptance, name criterion, environment/population, observed result, guardrail and accountable decision. A release can pass implementation checks while value remains unmeasured; report that state honestly rather than claiming either success or failure prematurely.

If a criterion/guardrail fails, record evidence and disposition (correct, revise bet or stop) with actual authority. Use existing authorization for release/actions; no blanket outward-facing approval checkpoint applies. Preserve tracker links and decision rationale in the checkpoint.
