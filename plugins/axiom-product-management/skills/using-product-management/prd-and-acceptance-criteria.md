# Product Specification Contract

Optional reference: use the parts relevant to the current question and selected policy. Existing records can satisfy the evidence; no fixed artifact count, review duration or reviewer count applies.

Record user/problem and supporting evidence; outcome hypothesis; alternatives including doing nothing; scope/non-goals; consequential constraints/dependencies; observable acceptance; owner; value/guardrail measurement; reversal trigger.

An acceptance criterion names context and expected behavior, including important denial/failure/accessibility cases. A value hypothesis names population, metric/source, target and observation window; do not fabricate a baseline. Separate implementation verification from the later product-value signal.

Use a short ticket/spec for small work and a durable PRD for multiple consumers. No fixed requirement count, one-metric limit or compulsory planning-pack handoff applies. Mark proposed versus approved intent and unresolved decisions; do not turn a polished document into false agreement.
