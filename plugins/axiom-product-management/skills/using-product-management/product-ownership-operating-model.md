# Product Ownership Loop

Optional reference: use the parts relevant to the current question and selected policy. Existing records can satisfy the evidence; no fixed artifact count, review duration or reviewer count applies.

Use RESUME → ORIENT → DECIDE → DISPATCH → ACCEPT → CHECKPOINT for standing ownership, adapting granularity to the current task. A single PRD or question does not require initializing every workspace artifact.

Resume from current workspace/tracker/release/metric evidence, not conversation memory alone. Orient to the user/problem, constraints and active bets. Decide against alternatives, success/guardrails and reversal triggers. Dispatch bounded delivery work with owner and criterion. Verify implementation/acceptance and value evidence separately. Checkpoint material decisions and next actions.

## Authority

Read the actual authority grant and current user instructions. Act within delegated scope; do not infer it from an ownership title. Earlier authorization persists. Outward-facing, irreversible or strategic actions may be delegated explicitly; the category alone does not require reapproval. Where authority is missing, prepare a concrete reviewable proposal and ask only for the actual decision.

Do not use tools to contact others unless authorized. Coordination can produce a draft or record without sending it. Preserve unrelated work and clarify custody for consequential state changes.
