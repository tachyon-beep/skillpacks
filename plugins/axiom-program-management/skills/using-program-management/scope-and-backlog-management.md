# Scope and Backlog

Optional reference: use the parts relevant to the current question and selected policy. Existing records can satisfy the evidence; no fixed artifact count, review duration or reviewer count applies.

Keep one authoritative backlog with stable IDs, acceptance criteria, owner and dependency links. Distinguish committed, proposed and deferred scope.

For additions/removals, record outcome/rationale, changed acceptance, capacity/dependency impact and actual decision owner. Reforecast consequential changes; do not hide additions in implementation detail.

Use slicing to reduce integration uncertainty and expose acceptance, not to meet fixed task duration or ticket-count quotas. Preserve unrelated work and project-specific release custody.
