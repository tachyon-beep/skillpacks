# Test Infrastructure Evidence

Optional reference: use the parts relevant to the current question and selected policy. Existing records can satisfy the evidence; no fixed artifact count, review duration or reviewer count applies.

Inspect test entry points, fixtures, isolation, dependencies and CI invocation. Trace key behaviors to tests and distinguish existing coverage from executed evidence.

Check whether imports, generated config, working directory and runtime services belong to the intended checkout/environment. Run focused checks when authorized and necessary; record failures and unavailable prerequisites.

Identify meaningful gaps: untested boundary/failure/race, misleading mocks, nondeterminism and tests that mirror implementation. Do not infer quality from test count or a universal coverage threshold.
