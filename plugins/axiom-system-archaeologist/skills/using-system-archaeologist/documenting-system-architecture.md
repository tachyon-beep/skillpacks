# Documenting Observed Architecture

Optional reference: use the parts relevant to the current question and selected policy. Existing records can satisfy the evidence; no fixed artifact count, review duration or reviewer count applies.

Describe actual entry points, modules/services, data stores, external systems, state and authority boundaries. Link each consequential relationship to source/config/runtime evidence.

Separate logical structure from deployment topology and intended design from observed behavior. Name dynamic/conditional paths and inspection limits.

Organize for the reader's questions. Avoid exhaustive symbol catalogs unless a real consumer needs them; do not force files for every module. Include baseline, coverage, source index and refresh triggers.
