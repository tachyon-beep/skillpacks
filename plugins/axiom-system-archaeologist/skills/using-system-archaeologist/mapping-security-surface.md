# Security Surface Mapping

Optional reference: use the parts relevant to the current question and selected policy. Existing records can satisfy the evidence; no fixed artifact count, review duration or reviewer count applies.

Inventory identities, permissions, untrusted inputs, secrets, stores, external calls and authority transitions. Trace representative paths to enforcement points.

Record assets/trust boundaries, attacker-relevant entry paths, observed controls and evidence gaps. Distinguish absence in inspected scope from proven absence throughout the system.

Prioritize concrete exposure and consequence. This is mapping/evidence; use dedicated security review for uncertain exploitability or policy decisions. A source inventory alone does not certify security.
