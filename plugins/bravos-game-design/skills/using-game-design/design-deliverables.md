## Playable ruleset

Before drafting the player-facing rules, load [mechanics and
dynamics](mechanics-and-dynamics.md) and silently run removal, always/never,
dominance, information, consequence, and extreme-state probes on the core
action. Require the mechanic claimed to create bluffing, negotiation, trust,
push-your-luck, deduction, cooperation, or another dynamic to contain the
decision-relevant information and incentives that can actually produce it.
Repair a collapsed core before polishing the rules.

Use this order so players receive information when they need it:

Write the rules as an executable procedure, not a design rationale. Keep
rationale in a separate review or mechanic trace. Test setup, first play, ties,
termination, recovery, always/never policies, and the central claimed dynamic
without designer intervention.
