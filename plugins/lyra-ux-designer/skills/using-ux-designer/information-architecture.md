# Information Architecture Review

Map actual reader/user tasks to content and actions. Use their vocabulary and
available usage evidence rather than the implementation module tree.

1. Inventory relevant destinations, entry points, ownership and existing links.
2. Identify the likely task path and alternatives for supported audiences.
3. Check labels, grouping, search, current-location cues and exits from dead ends.
4. Preserve important URLs/anchors or provide redirects on published reorganization.
5. Validate findability with a concrete lookup/task trial when it matters. A tidy
   sitemap alone does not demonstrate that people can find the right item.

Return a small path/label change, sitemap, or prioritized finding tied to a task.
Treat inferred personas and navigation preferences as hypotheses. Avoid arbitrary
menu/depth counts; use real constraints and observed failure.

Static docs-site mechanics live in `lyra-site-designer`; source/derivative lineage
and propagation in `muna-wiki-management`; reader research in
[user-research-and-validation.md](user-research-and-validation.md).
