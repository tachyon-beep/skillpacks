# UX Decision Rubric

Use for a broad design question only when a rubric helps. Start from actual user
tasks, observed constraints and product intent rather than inherited screens.

- Can the user recognize the current state and available next action?
- Does each surface serve a supported goal at the point of need?
- Are important choices, consequences and recovery paths legible?
- Does navigation reflect user tasks and vocabulary rather than internal modules?
- Do different inputs, capabilities and access needs have workable paths?
- Which claims are directly observed, measured, hypothesized or merely preferred?

For a finding, cite the triggering state/passage or behavior, user consequence,
and smallest complete remedy. For a proposal, state the hypothesis and cheapest
useful validation. Do not manufacture personas, complaint quotas or full journeys
for an isolated control fix.

Use [user-research-and-validation.md](user-research-and-validation.md) for human
evidence, [accessibility-and-inclusive-design.md](accessibility-and-inclusive-design.md)
for criterion-based validation and [ai-experience-patterns.md](ai-experience-patterns.md)
for probabilistic/agent surfaces. A model explanation is not observed usability.
