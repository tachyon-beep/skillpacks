# Visual Review Contract

Inspect actual screens at the affected sizes/themes, not only design intent.
Reuse the product's existing design system unless changing it is the task.

| Concern | Inspect |
|---|---|
| Hierarchy | Primary task, actionable status and consequence are easy to locate. |
| Typography | Readability, wrapping, zoom, long labels, mixed scripts and density. |
| Space | Related elements group clearly; narrow layouts and overflow remain usable. |
| Color | Semantic consistency, measured contrast and non-color status cues. |
| State | Focus, hover, active, disabled, error, loading and selected states. |
| Motion | Purposeful feedback and reduced-motion behavior. |

A palette, spacing scale or font is a design choice, not universal proof of
quality. Cite the actual visual defect, affected task and remedy. Distinguish
screenshot inspection from keyboard, assistive-technology and human task testing.
See [accessibility-and-inclusive-design.md](accessibility-and-inclusive-design.md)
for criteria and [interaction-design-patterns.md](interaction-design-patterns.md)
for behavior. Do not expand a local visual fix into a whole design-system rewrite.
