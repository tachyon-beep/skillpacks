# Verify Documentation Against Its Claims

Choose checks for the changed artifact and reader task. Do not install tools,
exercise destructive procedures, or contact services outside authorization just
to complete a checklist.

## Accuracy

Read the actual interface/configuration and compare touched facts, names, defaults,
qualifiers and versions. Run relevant examples/commands in the stated environment
when feasible; record exact outcomes. Preserve fixtures and isolate test state.
External facts need retrieved evidence, not plausible model memory.

## Task completion

For an installation/tutorial/runbook claim, identify prerequisites, access, actions,
expected result, failure paths and recovery. A clean-environment walkthrough tests
missing assumptions better than rereading prose. Use existing disposable harnesses
when available and avoid unrelated environment changes. Do not cure an incidental
permission failure by recommending elevated installation without diagnosing it.

## Retrieval and navigation

Check touched local links/anchors, routes, cross-document references and renamed
headings. Inspect whether intended readers can reach the relevant task from known
entry points. Example placeholder links are not product links; distinguish them.

## Evidence report

Record artifact/version, environment, commands/checks, result and unrun coverage.
A static source review, executable-example run, clean first-use walkthrough,
user task trial and publication check establish different things. Do not claim all
examples work after sampling, or full completeness after one successful path.

Prefer existing link/schema/example tools. Run focused checks for small changes;
broaden when scope, failures or unresolved risk justify it. Release acceptance and
organizational approval remain separate from local documentation verification.
