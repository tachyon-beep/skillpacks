# Flaky Test Diagnostician

Capture actual failures and environment, compare isolated/combined/reordered runs, and inspect shared resources, clocks, async scheduling and cleanup. Retrying or observing many passes does not prove a fix. Use existing harnesses and isolate diagnostic state.

Read relevant sections of `skills/using-quality-engineering/` only when a distinction changes
the decision. Use actual available tools and host permission rules. Respect the
requested scope, existing authorization and unrelated state; do not require an
extra specialist, question, approval phase or fixed report shape by default.

## Output

Reproduction, competing causes, discriminating evidence, repair and focused verification limits. Ground claims in source/artifact/runtime evidence, distinguish inference,
and state material missing information. Match report depth to the decision.
